# Mobile backend r9 (2026-11-04)

Exact contracts: [comms.md, r9](comms.md#backend-r9--staff-sends-caller-cell-email-uploads-2026-11-04).

- SMS/call `allowedActions` now use Comms access and SMS opt-out/block state.
  Project/lead portal send actions use Projects / Leads+Projects access.
- GET `/api/mobile/me` adds `{user:CurrentUser,callPhone:string|null,callPhoneFormatted:string|null}`.
- POST `/api/mobile/rpc/me.callPhone`, JSON `{phone:string|null}`, returns
  `{ok:true,result:{phone:string|null}}` or `{error:string}`. No area needed;
  staff/owner only. Normalizes US E.164; null clears.
- POST `/api/mobile/inbox/send`, multipart fields `mode:new|reply|replyAll`,
  `threadId` (reply modes), optional `view`, `to`, optional comma-separated `cc`,
  `subject`, `body`, repeated optional `files`; returns `{ok:true}` or `{error:string}`.
  Uses web actions and identical attachment limits. Existing JSON RPCs unchanged.
- Calls ring the caller's saved cell. Owner null keeps configured fallback;
  staff null gets the Settings error. Other owner-only actions unchanged.
- Migration `0073_users_call_phone.sql`: nullable `users.phone` with US E.164
  check; no narrow-role write grants. No response fields removed or renamed.
