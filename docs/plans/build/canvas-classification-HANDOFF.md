# Canvas result classifications — implementation handoff

Audited against the 285 registrations at base 8e66ed67, on t3/in-app-browser-agent-tools. Only the four assigned files are part of this change. No installs, build, browser, service or live/QA database actions.

## Contract and variants

The content catalog is all PermissionKey values except projects and ai; those remain separate access gates. Actor permissions never classify returned content. Financial labels follow lib/permissions.ts: estimates (including lead rough estimates), invoices (including job total/paid), purchase_orders, change_orders, bidding, cost_book, and money for remaining costs, budgets, rates and funding. Contacts require their owning lead/sub/vendor/communication area.

Each entry is the union of every possible result mode, including optional scope, include flags, read/write, replay, errors and empty results. The recorder at lib/ask-context-inputs.mjs:171 passes ONLY the tool name, so no argument-selected narrowing is claimed. This needs no new per-call recorder information. Unknown tools/variants still return full C and complete:false. A failed or empty call keeps the same conservative union as success.

Classification is of delivered results: writing a price but returning only an ID/ok does not expose that price. Internal SELECT/RETURNING rows discarded by a helper do not add areas. Project geometry, report/checklist records, file metadata and many mutation confirmations therefore add none (projects is outside C). File bytes are different: get_project_file/view_project_image retain full C. Canvas, canonical-doc, attachment and question tools add no additional tool-label areas because their independent synchronous gates record the actual inherited/source envelope or make provenance unknown before delivery. These are not generic harmless-reader exceptions.

Keep format version 1: existing stored full-C input labels and monotonic Canvas requirements are never shrunk or reclassified. Only newly ingested results use the audited narrower contracts. This cannot remove prior restrictions and requires no schema/recorder change. No actor-area inheritance or owner declassification changes.

## Full C (21 areas) retained

- **check_owner_permission**: Grant pub returns scope/reason/audit and staged results across all actions; no scope envelope.
- **enqueue_agent_trigger**: Returns the full trigger, including existing merged payload from another call. Trigger kinds do not type or classify payload content.
- **fetch**: Namespaced generic fetch returns complete records, knowledge content, project notes and money across kinds.
- **fetch_knowledge**: Complete arbitrary knowledge_items content/metadata without a trusted area envelope.
- **get_decision**: Generic decision summary/amount/recipient/decision_note across all decision kinds, with no typed per-result envelope.
- **get_operating_context**: Prompt includes unrestricted standing memory/instruction text and arbitrary trigger.payload, besides broad scoped financial/contact context.
- **get_project_file**: Returns arbitrary text/CSV/JSON/PDF/image file bytes or signed URL. Format and project metadata do not establish file sensitivity.
- **get_standing_instructions**: Approved agent_memories.summary/content can contain facts from any business domain; approval as an instruction is not area classification.
- **get_work_item**: Full work-item body plus unrestricted agent_runs.input_summary/output_summary and receipt labels can reproduce any prior tool/business result; no source-area envelope.
- **list_agent_activity**: Returns executions including tool traces and pending triggers with arbitrary merged payloads from any domain.
- **list_agent_memories**: Arbitrary pending/approved memory summary/content across domains.
- **list_owner_permissions**: Mixed-action grants with arbitrary scope/reason/audit and staged results.
- **list_pending_decisions**: Lists generic decision summaries/amounts/decision notes across all decision kinds; project scoping is not a content-area boundary.
- **list_recent_knowledge**: Arbitrary shared knowledge content snippets; time/scope filters do not restrict the content domains.
- **procedure_checks**: include_memories returns pending memory summary/content; open findings also quote arbitrary procedure/memory text across domains.
- **record_agent_execution**: START returns only execution_id, but FINISH returns the whole execution with prior tool_trace inputs/results, result_summary, next_trigger and cost_usd. Trace data can span every area.
- **request_owner_permission**: Grant pub includes arbitrary scope/reason/audit and prior staged-send result; action is variable, and scope/audit are not domain-typed.
- **search**: Unified search returns knowledge_items.content and work-item bodies across all business domains.
- **search_knowledge**: Unrestricted shared knowledge content snippets; project/lead/kind filters do not establish sensitivity.
- **stage_decision**: Returns a decision with arbitrary caller-supplied summary/content-derived fields and amounts, plus any deduped existing decision.
- **view_project_image**: Unclassified image bytes can be plans, invoices, screenshots or any other business record; image MIME is not a sensitivity label.
- **wait_for_decision**: Returns the generic settled/pending decision, including unrestricted summary/response fields.
