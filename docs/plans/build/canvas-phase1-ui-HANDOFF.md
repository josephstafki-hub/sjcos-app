## Item → implementation

- **Registration / responsive host:** `canvas/useCanvasFeed.tsx` registers four pure slots with Phase 0 `registerAskPane`; the small pane loads through client `next/dynamic({ssr:false})`. Phase 0 `AskContentPane`, host layout policy, splitter, history and focus coordinator are unchanged. Only PanelDock's existing Chat mount gets current Canvas selection and an exit-to-Chat callback. Host still owns 839/840 splitting, explicit dock expansion, phone sheet, 800×360 left strip/right action column, 48/20/56 rows and the single exit.
- **Feature off:** public compile-time flag derives strictly from server `SJC_CANVAS_ENABLED === '1'`. Off does not register, fetch identity/feed, or add DOM; existing SSR tests retain Phase 0 markup. A deployment must rebuild to change this compile-time UI flag; effective server availability still closes pixels on refresh without a rebuild.
- **Scope / feed:** authenticated server action admits the thread/person (or the empty new-chat view). Claims are tab-local and ephemeral. Thread/failure changes clear before effects; requests carry their claim; hidden views abort/unmount. Active feed cadence 2s, idle 30s, focus immediate. Newest-page backward `has_more` is distinguished from forward drain; terminal/failed runs keep draining to the cursor. Earlier canvases uses bounded backward pages. Availability changes invalidate the claim and cached code/frame; master-off redacts cached historical cards even with an empty event page. No source/title is written to storage or panel bus.
- **Cards:** run/canvas grouping merges highest committed version in that run, without duplicate cards across pages; card goes after its reply and before RunReview. Orphan and human events interleave by server time. Showing stays focusable with `aria-disabled`; older-version Open pins the exact version and stops following; deleted/unavailable/off/rejected/actual-tool creating states have fixed copy. New versions don't invent a committed card. Existing AssistantMarkdown remains unchanged and escaped. Actual show/update tool activity controls making/updating copy.
- **Pane:** title picker (up to server's 20 rows), About this diagram summary alternative, fuller Preview/Code and compact Show code sheet, Copy code, fixed source-fix/simplify prefills, selected-version context hint with 44px Remove control, no automatic send. Previous/Next, paginated 56px history rows with change note/maker/time, Latest/follow-latest, append-only restore confirmation and CAS request shape. Delete uses DELETE + one UUID per retry; pending/failure is title-free.
- **Renderer:** `/api/canvas/renderer` checks the current session/master/diagram/staff gates. It reads the vendored Mermaid asset once, invokes `buildCanvasRendererDocument` and verifies its pinned digest; only public library/document bytes are cached. Source never enters renderer URL/HTML, scripts, source maps or initial Chat payload. Child is exactly `sandbox="allow-scripts"`, opaque HTTP CSP, no CORS, no `allow-same-origin`. Parent validates exact WindowProxy + null origin + 128-bit instance/nonce, bounded port schemas, version/sequence, finite dimensions and SVG bytes. Ten-second load and three-second render watchdogs remove frame/close port; cleanup runs on abort/switch/hide. No generated SVG/HTML enters app DOM. The existing trusted renderer owns strict Mermaid configuration and SVG reconstruction.
- **Controls:** floating Fit/100%; fuller and any fine pointer/hybrid mouse add −/+. Ctrl/Command-wheel only over stage, drag pan, pinch, double tap Fit, focused-stage +/−/0/arrows; pinch release does not masquerade as double tap. Manual zoom clamps 25–400%. Stage is light with system fonts through existing renderer. Actual CSS dimensions and touch behavior require coordinator evidence.
- **Routes:** selected-version code is canonical JSON from `canvasGet(id,{version,include_source:true})`; source attachment is plain text with safe ASCII fallback plus UTF-8 filename, selected `.mmd`, strict sandbox/nosniff/private-no-store. Raw preview is a fail-closed Phase 2 stub. Render and SVG download are fail-closed while exports are disabled. Auth precedes version diagnostics; origin is required for render POST; errors retain child CSP and fixed envelopes. Trusted standalone/print wrappers reauthorize via `canvasGet`, use force-dynamic, DENY + `frame-ancestors 'none'`; wrapper headers cover proxy redirects and Next wrapper matches only, never `/api/canvas/*`. Output tracing explicitly includes `renderer-assets/mermaid-12.3.0.min.js`.
- **Standalone:** trusted full-height viewer with the same pane/source/version UI, authorized chat picker, reauthorization on focus/30s, immediate hide disposal, no title/code after availability changes. Ask-for-change/fix returns to the originating Chat with IDs/version/fixed action only; that Chat reauthorizes and rebuilds the explicit prompt. No source/title or token is passed in URLs. Print wrapper currently shows Internal draft, pinned metadata and source fallback; it does not call print or claim a PDF was made.

## 0108 derivative seam (must match before enabling SVG)

Current browser calls and future route expectations:

1. `POST /api/canvas/<uuid>/versions/<positive-int>/render`, same-origin JSON **exactly `{svg:string}`**. SVG UTF-8 ≤524288 bytes; account for JSON escaping separately when bounding the body. Reauthorize session, own thread/version/areas, recovery and current diagram/export gates; independently rebuild SVG with `validateCanvasSvg`. No source supplied by this endpoint replaces canonical source.
2. Success JSON **`{ok:true,canvas_id:string,version:number,renderer_version:string,sha256:string}`**, lowercase 64-hex digest of the accepted canonical SVG. Client checks matching canvas/version and hash shape before marking the drawing downloadable. Persist one immutable accepted hash per canvas/version/renderer tuple, replay equal hash without quota growth, reject changed hash with `RENDERER_HASH_CONFLICT` 409, and account retained bytes atomically. Render never creates a project file.
3. `GET /api/canvas/<uuid>/versions/<n>/download?format=svg`: authorize again, load accepted derivative, independently revalidate current policy/bytes, return canonical `image/svg+xml` attachment with safe `Title (vN).svg` filename, strict static sandbox/no-network/no-script CSP, nosniff, private/no-store, no CORS. Missing derivative: `EXPORT_NOT_READY` 409; export kill: `CANVAS_DISABLED` 503. Never fall back to unvalidated client SVG.
4. Core metadata must set effective `availability.exports` and include `svg` in `capabilities.download_formats` only once this seam is implemented. Current UI won't POST derivative bytes while exports is false. Drawing (SVG) is visible **disabled**; source `.mmd` works independently under `capabilities.code && availability.source`, as confirmed by coordinator.
5. Keep `SJC_CANVAS_PRINT_ENABLED=0` (default) until actual static derivative print implementation + Safari/device acceptance. The visible action additionally requires exports and a validated derivative. Current print route deliberately offers source/Open canvas only. PNG is not offered. Save-to-project-files remains hidden until its separate 0108 UI/backend work.
