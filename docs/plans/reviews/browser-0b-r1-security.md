Verified protections

- Browser namespace rules default-drop IPv4/IPv6, forwarding, DNS and UDP; the explicit exceptions are namespace-local CDP and two gate TCP ports. Gate upstream rules reject private ranges and allow public HTTPS plus the fixed resolver. No host CDP forwarding is installed. This is a disposable fixture topology, not proof of future production routing.
- FreshResolver checks CNAME/A/AAAA, rejects private and mixed answers (including additional records), repeats resolution before connection and pins the selected IP. Transport checks actual peer, CONNECT/Host/SNI agreement and upstream certificate hostname/chain. The transport permits one HTTP request per connection, avoiding keepalive authority reuse.
- Exact canonical Ed25519 manifests bind principal/task/run/boot, expiry and complete request identity. The synchronous `used.add` precedes durability awaits, so concurrent identical requests cannot consume the same pair. Exclusive durable manifest/consume/checkpoint files prevent replay after restart; failure burns authority. Restart refusal is safe even though it sacrifices availability. Fixture signing keys are deliberately separate from release-review authority.
- Patched target attachment admits only paused page/iframe targets in known contexts; Fetch and recursive child guards precede resume. Workers/unknown types refuse. Authentication handlers cancel challenges. `pageFor` checks the live boot and has a deadline. Headless-shell/component-extension changes do not widen the target allowlist.
- The barrier's swallowed revoke exception is not itself a bypass: `fail()` fences its boot synchronously; its launcher wrapper calls close in `finally`, and close bounds the policy call before killing the child process group. However, not all fatal paths enter this wrapper (required fix 1).
- Provisioning freezes verified source bytes before running subsidiary installers; runtime destination ancestors are checked for root ownership/non-writability; installation uses atomic replacements and rollback journals. The AppArmor attachment names two exact pinned binary paths. It is explicitly unconfined with userns permission, not an additional filesystem/network sandbox. No broad userns sysctl change is present.
- Release remains disabled and requires independent signed attestation. DB-less candidate operation and absent product wiring are correctly disclosed. No page-content-to-model operator integration was demonstrated here; prompt-injection safety of later observation/tool wiring remains a later gate, not something these 43 cases establish.

REQUIRED fixes

1. **High — unify fatal shutdown and provide independently supervised controller-loss cleanup.** `lib/browser/controller.mjs:58`, `:81`, `:86`; `lib/browser/root-fixture.mjs:92`; `lib/browser/launcher.mjs:72`, `:73`, `:79`, `:88`; `deploy/browser/transport_runtime.py:534`. Controller policy failures and the gate exit handler call the policy closure directly. That closure revokes authority/gate access and removes Fetch handlers, but does not close the browser or fence the separate Playwright boot. Only the barrier's wrapper invokes launcher close. Additionally, the detached Chromium child's cleanup relies on JavaScript exit/signal hooks, which do not run on SIGKILL; there is no independently observed controller-liveness channel in the gate's transfer loop. Exact change: introduce one idempotent fatal-boot path that synchronously fences both policy and barrier, initiates bounded gate/receipt cleanup, and independently kills/awaits the browser group; route every controller/gate failure through it. Supervise abrupt controller death outside that controller (with a bounded gate liveness lease/channel and browser cgroup cleanup). Concrete repro for coordinator: load a page with a timer, cause an unauthorized Fetch or kill the gate, and inspect browser processes/CDP before fixture finally cleanup; the direct policy path does not request browser shutdown. Separately SIGKILL the controller while a slow authorized transfer is active: its exit hook cannot kill the detached browser and the gate has no ongoing liveness check during that transfer. Require bounded disappearance of browser/gate sockets and no post-revocation transmission, not just eventual suite teardown. No unauthorised network transmission was independently demonstrated by this review.

2. **High — replace graceful-revoke substitutes with real fault acceptance.** `lib/browser/root-fixture.mjs:80–86`, `:138–141`, `:169–189`. The controller-loss cases explicitly await `policy.revokeListener()` BEFORE disconnecting the endpoint; fetch-detach also explicitly revokes after detach. They can pass even if automatic loss/detach cleanup is broken. `controller-loss-keepalive` uses a raw one-request client against a transport that closes every response, not a retained connection survival test. Gate-crash only asserts a controller `boot_revoked` event and absence of gate-uid tasks, not browser death. Exact change: use a separately supervised controller process; pause at measured consume/prewrite and active-transfer boundaries, then kill/disconnect it without calling revoke. Detach the actual session without a fallback explicit revoke. Assert the named fault occurred, independent socket closure, durable unknown/no-retry, and browser-process disappearance before test cleanup. Count only explicitly identified supervisor PIDs as allowed survivors, and fail unreadable identity checks unless disappearance is confirmed. Concrete mutation test: disable the automatic disconnect/detach cleanup; each corresponding acceptance case must fail. The current controller-loss sequence still revokes successfully with those handlers removed. Re-run root acceptance after fixing, and retain independently inspectable hashes/artifacts for review.

3. **Medium — make evidence and link-control validation semantic and fail closed.** `lib/browser/acceptance.mjs:6–23`; `lib/browser/root-fixture.mjs:225–241`. Reproduced offline: load either final1 report, replace every case's measurement with `{fake:true}`, and call `validateEvidence(e,{runId:e.runId,kind:e.kind})`; both return `{ok:true,releaseReady:false}`. Also, a synthetic raw-IP pcap containing fe80:: → ff02::, next-header ICMPv6, hop-limit 1, type 135 and arbitrary `SECRET-IN-NDP` bytes is classified as one linkControlPacket and zero privatePackets. The classifier validates neither ICMP code/checksum/length nor the hop limit/options; its comment that these are kernel packets with no payload is not established. Exact change: define required per-case fields, bounds, failure counters, event/receipt/pcap hashes and ordering/fault predicates; cross-check aggregate values and artifact hashes before accepting evidence. Reject placeholder/contradictory measurements. For the IPv6 exception, validate complete protocol-appropriate NDP/MLD structure and source/interface/direction provenance, with sufficient capture length, or exclude only independently attributable fixture-kernel control traffic. Malformed/truncated/unattributable packets must fail. Add the two above offline negative fixtures. This is an acceptance-integrity defect, not proof that sandboxed JavaScript can emit raw ICMPv6; independent signatures remain a separate release safeguard.
