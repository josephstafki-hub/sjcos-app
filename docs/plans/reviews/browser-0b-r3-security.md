## Residual boundary decision

**Acceptable for this plan; no further required closure.** The final nonblocking-send guard is the documented dispatch linearization point. Once that fence observes death, it raises before the send; the watcher also cuts pending IO. There is no asynchronous scheduling gap between the guard and syscall. Physical process death can still occur after a successful check and before/during that syscall, and bytes already queued can arrive later. This is the unavoidable in-flight boundary for the already-authorized, exact, consumed request, which remains unknown and cannot be retried. It does not permit a fresh authorization or a request to start after an observed dead fence. The plan explicitly permits an authorized in-flight final request to be unknown. The revised RESULT correctly discloses the syscall race instead of claiming a literal zero-time physical-death guarantee or describing only response drainage.

The active-response fixture still waits for independent controller-loss observation before releasing its reader. Its pass establishes post-observation CUT, not an independently measured physical-death-to-CUT latency. That limitation is now explicit and is optional measurement work, not an outstanding dispatch bypass.
