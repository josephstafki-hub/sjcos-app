## Verified items

1. **R1 consent invalidation: fixed.** `0115_browser_phase1_runtime.sql:193–199,466` locks the task, refuses consent while public, checks the consent proof against the current context/revision and clears all old consent on takeover while rotating streams. The DB regression attempts advance consent, injected historical consent, stale public proof after takeover and fresh private consent. I additionally ran a website join using an old proof while an actual `sjcos_browser` LOGIN held the uncommitted takeover: after commit, join failed `BROWSER_REVIEW_STALE` and consent remained NULL. Both transitions serialize on the task row. Fresh consent alone does not release frames.

2. **R1 concurrent frame nonce: fixed.** `controller-rpc.mjs:90–99,123–124` claims the validated nonce synchronously before awaiting authorization. The actual production helper rejects a simultaneous identical attempt, delayed-past-expiry authorization, disconnect during authorization and replay after failed authorization. The socket handler invokes that helper after signature/time/schema validation and rechecks current authority, expiry and closure before subscribing. Per-frame authority is checked again before delivery. These are in-memory tests; no listener was started.

3. **R1 private Watch audit ACK: fixed on the production path.** `0115_browser_phase1_runtime.sql:944–951` binds the audit event to task, owner, sid, viewer, context, stream and consent serial, then requires a covering independently acknowledged checkpoint. Real SQL/runtime-access tests reject no ACK, wrong stream binding, sink outage, renewed consent with an old ACK and changed stream generation; recovery succeeds only after verified checkpoint commit. Lost SQL ACK retains/replays the original spool record. `production-bridge.mjs:139`, runtime access, frame handshake/per-frame checks and `web.ts` frame recording enforce that predicate. Narrow LOGIN tests deny protected table writes, forged authority and owner escalation. The QA exception below prevents unconditional approval of the combined candidate.

Actual DB lifecycle revocations for master/staff flags, session, rights and inactive person close fenced private contexts. Discovery commits a pending review, blocks the original Fetch and requires a new deliberate action; approval does not replay it. Fractional pointer/wheel coordinates survive unchanged inside the finite half-open viewport bounds; upper edges, negative and nonfinite coordinates refuse.

5. **Checkpoint replay:** exporter tests reject stale/forged replay envelopes, altered original signatures/records, future original timestamps, rollback and conflicting heads. Both signatures are verified; replay_at cannot independently authorize an event or change its identity. An authenticated fresh replay of old durable evidence is intentionally valid for recovery, but cannot cover a newer consent event above that checkpoint or match a changed viewer/stream/consent binding. ## QA boundary ruling and optional items

- **Remove from production: required, as above.** Static symlink/traversal/alternate-path attempts are refused by the fixture/path tests; production Unix client retains the original fixed root-owned paths when inactive. QA paths use lstat followed by later file/socket operations, so they are not immutable handles against a trusted-directory-owner rename race. Neither path checking nor valid signatures using the QA keys establishes independent audit custody. I found no static symlink/socket trick that bypasses the ordinary database-name guard.
- **Inactive behavior:** missing either QA environment variable returns null without DB I/O, and the ordinary loader/socket/signature branches remain selected; tests confirm that functional behavior. “Byte-for-byte unchanged” is not established: product source, imports/module graph and asynchronous entry-point work changed, and no build/artifact comparison was permitted. The static fake-module import is present even when the runtime branch is inactive.
- **Expired viewer limit: optional for this security gate, recommended availability fix.** `0115_browser_phase1_runtime.sql:210` counts every `left_at IS NULL` viewer, including expired attendance/session rows. I reproduced an expired owner Watch row blocking a fresh device with `BROWSER_RESOURCE_LIMIT`. It can lock out legitimate reconnects but does not authorize an outsider or expose private data; identity/claim checks precede insertion. Retire invalid sessions/expired viewers under the task lock, clearing their control/consent and rotating stream identity, then count active eligible viewers. Add reconnect and simultaneous-join regressions; do not merely exempt expired rows while allowing unlimited later resurrection.
