## Required fix

1. **P1 — stalled response bodies defeat the Close deadline and Try again.** `lib/consult/transport.ts:13–15`, `lib/consult/ui/controller.ts:44`, `:518`, `:537`. Fetch resolves when headers arrive. `deadlineFetch` immediately clears its abort timer, while `post()` subsequently awaits `r.json()` outside that deadline. A server/proxy that sends headers and then stalls the JSON body can therefore hold `resumeClose()` and its boolean guard forever. In-flight joining is correct for normal sends, but cannot recover this state.

   **Repro:** in memory, return a Response with a ReadableStream whose body stays open from the actual global fetch used by `post`. Start `resumeClose()` with an already persisted request, then invoke public `close(null)` as Try again does. Observed: `guard=true, requests=1`; retry returns with `guard=true, requests=1, step=sending`. Its UI timer can only show timeout again. Releasing the original body finishes with `step=done`. When the first attempt lives inside `drainPromise`, retry instead joins that hung promise; either arrangement cannot initiate recovery. Thus the UI builder's concern is real, although an ordinary native fetch stalled *before headers* should abort after 15 seconds. A 26-second hold followed by successful release does not disprove an indefinite-body stall.

   **Fix:** bound the complete request including body consumption, mapping a timed-out read to transient `http_408`; do not swallow timeout/abort as an empty success body. Give Close an owned attempt promise/abort controller. Try again must abort and settle an expired attempt, release its guard, and replay the identical durable request. Fence late completions so a superseded attempt cannot overwrite state. Do not simply reset the boolean while an old request can still commit. Add regression tests for headers-with-stalled-body, retry while the guard is held (both direct and drain-owned attempts), lost acknowledgment with one server effect, and late old completion. Preserve automatic exact-request retry and the existing 155 passing checks.

Physical-device cold-offline answers/photos/Close, revoked reconnect and expiry while open, missing-device recovery, and retained-build recovery remain coordinator acceptance work. They are evidence limitations, not additional invented implementation defects.
