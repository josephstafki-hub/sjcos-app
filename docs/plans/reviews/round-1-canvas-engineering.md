## Wrong or invented

- **Shared contract is not shared.** Canvas §3 names `PanelContentPane`, one activePane union and a 960 px split with 360/480 minima; browser §6.2 names `AskContentPane`, a registry/snapshot contract and a 720 px split with 320/380 minima. Browser expands a 400 px dock automatically; Canvas explicitly preserves 420 px and tabs. Canvas §8.1 creates `interaction_surface` in 0105 and says Browser consumes it; browser §4.1/§9.1 creates `launch_source` in 0100 and §6.2 says no shared migration. No agreed integration or provenance contract exists yet.
- **Matching DB fields does not prove transport provenance.** Canvas §5.2 promises denial of claimed HTTP identities, but current `principalRef()` prefers HTTP AsyncLocalStorage (`mcp/sjcos-mcp.mjs:153–159`), whose principal, run and profile are supplied by authenticated HTTP headers (`:3146–3153`). `internalCall` forwards those values (`:195–229`). An external MCP caller supplying a real matching live panel run and person can satisfy the proposed DB comparisons; those comparisons alone do not prove the call came from that panel runner.
- **The strict save schema cannot implement the audience UI.** §8.4 accepts only `{request_id,project_slug,filename?}`, while §9 requires Joe to submit an owner-only/share-with-staff decision and required-area checklist. There is no field or separate command carrying that decision. The conservative staff rule also snapshots the creator's permissions only at creation: a later permission increase plus update without expanded model labels can put newly readable data into an older, less restricted canvas/file.
- **History has no complete wire contract.** §5.4 says to drain a thread event cursor through “the list endpoint”; the only human GET specified is per-canvas version history (§5.3), while MCP list is canvases sorted by updated time, not a thread event feed. Neither implements cursor-ordered failed-run/human-action cards. Read/list result shapes are “appropriate” rather than exact (§5.1). §5.3 says DELETE for deletion, §8.5 says POST. Selected-version source retrieval and capability/kill-state propagation are not concretely specified for the web client.
- **Saved-file deletion conflicts with existing code.** `lib/file-trash.ts:24–38,68–90` queries every FK to files and refuses a referenced file. The new save FK therefore blocks promised deletion; with no narrow SELECT on the private save table, its generic FK scan also fails for narrow-role trash callers before it can decide whether any file is referenced. Restoring reinserts the original files row (`:105–124`), but ON DELETE SET NULL does not restore a save-ledger association/access-policy join. §8.4 does not address this path.
- **Existing floor versions are not fully immutable or globally serialized.** Unique `(design_id,number)` already exists (`db/schema.sql:3264–3272`); snapshots have bigint IDs and no source-rev column. MCP snapshot creation (`mcp/floor-tools.mjs:561–567`) and web save/restore (`lib/actions/plan-designs.ts:183–215`) independently allocate MAX+1 without the proposed design lock. Web deletion removes versions or whole designs (`:164–171,221–230`). Canvas locking only its new writer does not make these writers cooperate or define what deletion of a referenced snapshot does.
- **Retention conflicts with physical thread deletion.** `lib/actions/ai-chat.ts:410–412` physically deletes the conversation; `db/schema.sql:2535–2555` cascades its messages and linked dev_agent_runs. The proposed canvas/version/request/event FKs need an explicit lifecycle policy to preserve the promised immutable provenance shells and 30-day purge. “Deleting a thread cascades the same tombstone/purge schedule” does not implement that policy.
- **Several assertions lack an enforcement location.** Per-owner locks do not serialize the 1 GiB global quota across owners. Derivative uploads can add substantial bytes outside the create/update transaction. No concrete global counter/lock, durable rate-window representation, scheduled maintenance caller, purge lease storage or post-backup deletion ledger is specified. A route plus “configure maintenance” is not a scheduler, and tombstones rolled back with the backup cannot replay themselves.
- **Some baseline line references are impossible, not merely shifted after implementation.** There is no source diff from `cf305728` to this HEAD. `proxy.ts` ends at 198, not cited 228–233; API bypass is at 190–196. `lib/api-auth.ts` ends at 74, not 87–106. Floor page ends at 65, not 77; upload public/private helpers begin at 85/102, not the cited private-helper anchor 110. Correct the repo map to the actual reviewed baseline.
