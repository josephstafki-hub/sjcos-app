## Wrong or invented

- **§3.2's “controller raw CDP session alone owns Target autoattach” is false for the chosen unmodified runtime.** The actual pinned 1.64.1 `coreBundle.js:39775–39785` calls `Target.setAutoAttach` on connect; `:39015,39059` autoattaches child targets and calls `Runtime.runIfWaitingForDebugger`; `:39230–39239` resumes/autoattaches workers. Omitting `route`/`httpCredentials` does keep Playwright's Fetch enablement off (`:37450–37475`), but does **not** remove its target/resume machinery. A separate raw controller session cannot be described as the only owner without a supported coordination mechanism or a patch.
- **§3.2 assigns full-body authorization to the wrong mitmproxy event.** `requestheaders` has an empty body. It cannot wait for the full body/HMAC as written and also allow the normal pipeline to read that body. Full request authorization belongs after bounded nonstreaming body collection, with the pre-body hook enforcing headers/limits. Merely naming an addon and a future packet-capture test does not supply that working event ordering. [mitmproxy event contract](https://docs.mitmproxy.org/stable/api/events.html), [buffer/stream options](https://docs.mitmproxy.org/stable/concepts/options/).
- **§7.3 mixes two different final-action protocols.** Step 2 consumes an exact request-bound action; step 3 then allows a pre-click adapter click that creates the request. §3.2 creates the actual digest and unique flow nonce only at the gate, and §9.1 records `request_digest` / `dispatched_flow_nonce`. A before-click review does not yet have that request/nonce; the specified consumer signature does not carry a later request-binding step. Calling a manifest “exact” does not define how generated CSRF fields/multipart bytes bind to the single allowed actual flow. The buffered-request path is coherent; the pre-click path needs its own explicit ordering.
- **Exact read approval exists only in prose.** §7.1/§8.1 require exact person-confirmed URLs and path/query/resource value policies. `/tasks` and `/sites` (§10.2) accept only origin/role entries; the §9.1 task origin manifest and §9.2 web catalog do not define a read-URL/value-manifest record or update. The start sheet confirms origins and explicitly has no address bar. Thus an adapter-free initial navigation/link cannot acquire the exact read authority the gate requires without inventing a new contract or weakening the policy to origin-level approval.
- **Phase 1 offers take-over before its required privacy gate.** §§5.2/6.1 require permanent private transition and output draining before even a pointer focus. Phase 1 nevertheless enables desktop/iPad take-over with “public anonymous pages only”; Phase 2 says it enables “private take-over,” and puts `browser-private.test.mjs` there. Vault off cannot make arbitrary manual input public or defer this prerequisite safely.
- **§8.2's file lifecycle overlooks a real repo coupling.** `lib/file-trash.ts:24–38` discovers every FK to `files` and SELECTs its referencing table. Adding `browser_file_links.file_id` while §9.2 denies agent SELECT will fail an ordinary agent file deletion even when no browser file exists. For a browser file, RESTRICT plus a persistent link also prevents the actual `trashProjectFile` delete (`:79–90`). Saying “trash/restore retains envelope/AAD” does not specify the required ledger unlink/reserved-ID/relink protocol. Canvas §8.4 already handles its own analogous FK, but not Browser's FK automatically.
- **Owner review is not expressed in the adopted host contract.** Shared H2 selection is scoped to authenticated person/tab/thread; H4 aliases snapshot user/thread to the original run principal/conversation. Browser §6.2 supplies exactly the staff initiator/thread in its snapshot, while §4.1 forbids Joe from acquiring that staff chat. The phone link (§6.3) says it opens the staff task directly in Operator but never defines which owned thread/claim hosts it or how the host renders review without loading that conversation. API permission to join is present; the selection/context integration is missing.
