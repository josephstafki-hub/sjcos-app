## Verified sound

The source inspection supports the plan's identification of prerequisites. These are changes to build, not protections supplied by today's code:

- `lib/session.ts` has the development signing-key fallback, no tracked sid, Bearer fallback and cookie-only logout. `lib/api-auth.ts` and `lib/dal.ts` recheck active users/areas and revocation; DAL reads are React-cached. `lib/permissions.ts` does not confer approval authority through visibility. The proposed separate live-session verifier and fresh stream/dispatch checks are necessary and concrete.
- `scripts/run-claude-agent.mjs:868–1005` resumes conversation CLI state, incorporates unseen history, allows the SJC server broadly, conditionally attaches personal Chrome and gives operator children the app environment. `lib/authority/run-profile.mjs` currently has only operator/business profiles. The proposed exact browser tool list, isolated settings/environment/rendezvous, removal of the optional hook and history partition address these actual paths.
- `mcp/interact-mcp.mjs:54–151` autoallows read-like names and persists arbitrary permission inputs. The revised browser-specific deny-only permission handler, bounded ask-human channel and independent web approval path avoid using that mechanism as a browser security boundary.
- `lib/owner-grants.ts` has general decision/consume paths and best-effort result logging; `lib/owner-grant-types.ts:86–130` accepts wildcard actions and optional target binding. Browser-specific exact grants, guarded SQL consume and rejection by generic approval/Telegram surfaces are explicitly required before release. Concurrent approval cannot consume twice; original run identity survives later turns. Unknown remote outcomes never automatically refund or retry.
- `lib/db-login.mjs` and `deploy/db-roles.md` explicitly permit owner fallback today. The bootstrap/manifest have four narrow roles and backup's broad read membership. The plan requires a fifth role, zero ordinary-agent browser-table access, function-only service authority, revoked PUBLIC EXECUTE and real-login tests; it does not mistake SET ROLE for session_user verification.
- `lib/backup/crypto.ts` uses age or CBC/PBKDF2. The vault correctly specifies independent authenticated envelopes rather than copying that backup fallback. `deploy/nginx-sjcos.conf` has ordinary app/MCP proxying and MCP SSE support, not a browser/CDP route; `deploy/sjcos-tunnel.service` routes the public hostname through TLS nginx. The planned authenticated SSE path requires neither public CDP nor a raw WebSocket bridge.

Fresh threat-model conclusions:

1. **Local host/CDP and SSRF:** separate service identity, private namespaces, narrow signed Unix RPC and root-owned network policy address other local users. Public/alternate app hosts, public host IP aliases, private/mixed DNS answers, redirects, IPv6/embedded forms and metadata are denied independently of model decisions. Target autoattach, disabled workers/alternate transports and the request gate cover child targets and interceptor failure. A release test must prove the two context listeners cannot cross; the plan already makes failure an admission blocker.
2. **Submit bypass and replay:** Enter, form.submit(), disguised GET actions, timers, beacons and JavaScript payments still need authorized upstream requests. No model evaluate/devtools/CDP interface exists. Direct human final clicks require correlated fresh input and the same exact snapshot/owner authority; ambiguous clicks fall back to review. Staff company saves, uploads and purportedly nonbinding requests also require Joe. Tokens bind immutable action/run/context/document/control/request data and are consumed once under locks.
3. **Injection and secret channels:** private observations are eliminated, not filtered after capture. Staff delegated viewing is independently eliminated. Prompt injection in public pages has neither privileged history continuity nor arbitrary SJC tools/network release authority. Browser autofill/password management, traces, console/error dumps and generic file/model readers are explicitly closed. Sanitizing a document does not authorize revealing its content to staff or the model.
4. **Viewer hijacking and attendance:** cookie/session/viewer/device/control/stream/frame epochs, CSRF/Origin checks and one-use signed bridge commands fence cross-device input and stale takeover. Joe must explicitly join; his presence cannot replace the staff initiator. Background/mobile Bearer/voice/Telegram launches cannot claim panel provenance. Host selection is display state, never authorization, and context switches clear private content per the shared host contract.

## Vulnerabilities / gaps

**No remaining required plan-level security finding.** The design deliberately refuses unsupported sites, protocols, delegated outputs and unsafe files. It does not claim that arbitrary authenticated pages remain model-readable or that a site cannot misuse a password delivered to its legitimate login endpoint.

Runtime implementation remains unverified: request buffering and failure behavior, Chromium sandbox/target handling, CLI restrictions, actual local-UID isolation, file-parser bounds, encrypted-file route coverage, and deployed nginx/Tunnel behavior require the already specified acceptance gates. No browser, server, build, test suite, DB or service was run for this review. An implementation that omits or fails those gates does not inherit these scores.

The documented trust limits are appropriate: the design does not defeat root/compromised trusted service code, a dishonest destination portal, or a human deliberately copying what they are authorized to view. Heartbeats cannot prove continuous human attention. These are acknowledged boundaries, not missing plan fixes.
