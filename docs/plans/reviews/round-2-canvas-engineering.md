- **The existing harness does not change `session_user`.** `tests/_harness/testdb.mjs:115` creates the narrow roles NOLOGIN; `:132` implements `urlAsRole` as connection `options=-c role=…`. Thus it changes the effective role while `session_user` remains `sjctest`. `tests/db-roles-paths-db.test.mjs:73` uses that mechanism. With §8.1's new SECURITY DEFINER/session-user check, tests either treat these as trusted-owner sessions or refuse ordinary background writes too, depending on how the website-owner comparison is initialized. Neither proves actual narrow-login behavior. This does not invalidate session_user as the production boundary; it invalidates assuming the current role fixture proves it.
- **A journal hash chain cannot prove freshness by itself.** §§8.5/11 require replay through acknowledged high-water but specify local fsync before delete acknowledgment and independently replicated journal with monitored lag. No acknowledgment high-water independent of both the restored DB and a potentially stale replica is defined. If deletion N was acknowledged locally, off-box replication has only N−1, and the operations volume is lost, restoring an old DB plus the valid N−1 chain supplies no evidence that N ever existed. “Latest required journal” is not verifiable from those two inputs. This is a missing restore protocol detail, not a request to change Joe's retention decision.
- **Three installed-doc citations have the wrong path prefix.** In Canvas §2 line 72, `02-guides/lazy-loading.md`, `02-guides/content-security-policy.md` and `03-api-reference/05-config/01-next-config-js/headers.md` do not exist directly below the stated `.../next/dist/docs/` root.
