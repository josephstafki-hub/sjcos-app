### New mechanisms reviewed

1. **One-minute review and notifications (§6.3, §7.3, §10.2): sound.** The actual gate deadline starts at headers and is never extended by notification delivery, re-ask or inactivity suspension. Links contain task/action IDs, not tokens or credentials. Specified notices use trusted task/action facts, not private page strings, images, OTPs or request bodies; this is not a promise that job names/amounts are hidden from Joe's notification previews. Telegram/native Bearer paths cannot approve. Copied or expired links require fresh authorized web access and resolve their original immutable outcome. Re-ask never replays a lost request; consumed/uncertain actions retain unknown status.
2. **New shell routes (§4, §6.2, §10.2): sound.** `/today` resolves a fresh owner claim; `/logins` grants personal login management under the ai area without opening owner settings. Common handler guards apply independently of layouts: fresh cookie/user/record authority, exact Origin, CSRF, Fetch Metadata and bounded JSON on mutations. GET cannot acquire control or approve. Staff ownership and Joe-only named sharing remain server-derived.
3. **Public take-over and reset (§5.2, §6.1, §12): sound.** Suppressing Joe's confirmation changes presentation only. Privacy and output draining precede control/input even before vault rollout. Fresh browser destroys the old context and revokes its identities/cards/profile restore; no cookie cloning, old-buffer publication or unhide path. Runtime hostile-page canaries gate first take-over.
4. **Delegated login and 2FA (§5.2, §6.4, §7.2): sound.** Named access does not enable generic delegated browsing. The first reviewed adapter supplies exact login-only approval; company authority is not bundled. Joe alone handles shared-login code/CAPTCHA and private viewing. Staff never receive OTPs, pixels or arbitrary input access, including after Joe hands back control.
5. **Refusal and lookup review (§6.3, §7.2–7.3, §8.1–8.2): sound.** Don't send cancels an undispatched flow without resume/retry; it is distinct from take-over. Exact job values and recipient are bound to a company lookup action and one-use owner grant even for GET. Public read approval cannot activate company entries, and Phase 1 refuses these releases outright.
6. **Owner layer over a staff task (§6.2, §9.1–9.2): sound.** Viewing Joe/session and immutable staff provenance are separate identities. Local thread must be Joe-owned or null; no staff messages, attachments, run polling or history are fetched or copied. Claim expiry/logout/area loss revoke display access; claims grant neither private pixels nor approval/control. Task/action/grant locking, immutable run association and exclusive device control fence concurrent joins, replacement and decision/resume races. Joe's presence never replaces staff attendance.
7. **Interception ordering (§3.2, §12): sound at plan level.** The attested Playwright patch makes one owner await the security barrier before every target resume; unknown workers/targets close. Header checks reserve bounded storage, then full nonstreaming bodies reach request authorization, then frozen bytes may transmit. Uncaught addon failures require the fail-closed dispatcher, not ordinary error logging. Official [mitmproxy event documentation](https://docs.mitmproxy.org/stable/api/events.html) confirms requestheaders precedes body availability and request sees the complete body; disabling streaming is essential. The [options reference](https://docs.mitmproxy.org/stable/concepts/options/) supports lazy connection configuration but explicitly requires checking the installed options. The plan correctly makes exact-version pinning, peer/SNI checks and real packet-capture failure fixtures release prerequisites.
8. **Pre-click actual-request binding (§7.3, §9.2): sound.** Approval authorizes one reserved click with the gate closed, without spending a grant on an imaginary request. CAS prevents a second click. Actual full bytes must match fixed business values, typed frozen-form CSRF provenance and every multipart part before binding digest/nonce/listener generation and consuming once. Extra/mismatched flows fail closed. Independent audit acknowledgment still precedes transmission; a crash cannot rearm/replay, and possible transmission becomes unknown.
9. **Read-URL manifests (§8.1, §9.1–9.2): sound.** Exact canonical URLs, value/header provenance, immutable revisions, session expiry, parent document epochs and atomic use budgets replace implicit origin permission. Discovered resources default blocked; hash-shaped paths do not establish static provenance. Company manifests activate only through the linked owner action and still require actual-flow consume. Edits/navigation/replacement invalidate affected proofs without rewriting an approved action.
10. **Trash/restore (§8.2, §9.2, §12): sound.** Only the exact managed FK is excluded from generic reference scanning; business-reference checks remain. Human-authorized lifecycle commands and direct-DML guards preserve ciphertext, provenance, delegated Joe-only ACL and immutable reserved ID. Same-ID restore preserves AAD; purge_pending cannot restore/decrypt. Locks, revision checks and reader publication/unlink proofs handle restore/purge races and crashes. No narrow ledger SELECT or generic JSON restore bypass is introduced; reader/guard compatibility survives rollback.
