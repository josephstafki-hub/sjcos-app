# QA Run — 2026-07-04 (full app test + lifecycle walk)

**How this was tested:** headless Chromium (Playwright) against the live prod build on
`localhost:3017` with a real owner session. Every page screenshotted and checked for
render/console/server errors. Then a clearly-marked TEST lead was created through the UI and
driven through the entire lead pipeline (intake → score → stages → Qwen rough estimate →
real Gmail send → convert), and the resulting project was driven through all 9 stages and
every tool tab, including a real client login exercising the portal (selection approval,
3 e-signatures, PDF review, messaging). All TEST data was deleted afterward — prod is back
to exactly 10 leads / 46 projects / 28 subs / 1 user.

**Notes:** 2 real emails were sent during the test from the Gmail integration (the Qwen rough
estimate to josephstafki@, and the completion-outreach warranty email to
testclient-qa@sjcarpentryllc.com, which may bounce). They're in the Gmail Sent folder.

## What works (verified end-to-end)

- All 33 routes return 200 with **zero** console errors, hydration failures, or 5xx.
- **Lead lifecycle:** New-lead modal → auto-score on create (HOLD 60% w/ honest rationale) →
  intake answers persist → re-score after enrichment flips to GO → all 5 stage moves → Tasks,
  Activity log (all moves logged), contact edit → Qwen rough-estimate draft (real line ranges
  matching budget) → **real Gmail send** → convert to project (lands at floor_plan, linked,
  intake address carried into project header).
- **Project lifecycle:** all 9 stage advances via the header button; stage→tool-tab mapping.
- **Design tools:** floor plan upload (v1), mood board add, selections sections w/ budget
  bars, push-to-client.
- **Estimating:** cost-book CRUD, estimate create, line from cost item (unit-cost snapshot),
  takeoff bulk add, recompute math verified to the cent, send-for-approval.
- **E-sign loop:** design + estimate + contract all signed from a real client login;
  estimate flipped to `approved` on sign; portal-scoped PDF serve returned a valid PDF.
- **Approval gate:** checklist went green only after design signed + selections approved +
  estimate approved; Generate contract produced PDF + DOCX into Files and a `sent` request.
- **Execution:** sub assign w/ role, schedule generate-from-template, daily log, punch
  add/complete, blank invoice draft, change order with real Qwen scope draft + send,
  safety orientation gen, permit packet PDF.
- **Portals:** real client login redirects & scopes correctly; approve/decline; two-way
  messaging (client portal message showed up in project Comms and Team Chat unread badge;
  owner reply flowed back).
- **Warranty stage:** completion outreach fired exactly once (`closeout_outreach_at` set),
  auto social draft was created, client portal switched to warranty mode w/ claim form,
  /warranty lists the project.
- **Closeout docs:** certificate of completion + final lien waiver PDFs generated.

## Bugs found — TO-DO (priority order)

### P0 — broken or misleading in front of real users

1. **Settings → Team & roles → “Add user” silently does nothing.**
   `components/settings/SettingsClient.tsx` — the submit button has
   `onClick={() => setOpen(false)}`, which unmounts the modal/form before the
   `createUser` server action fires. Verified 3×: form filled correctly, modal closes,
   no row inserted, no error. **Joe cannot provision client/sub portal logins.**
   Fix: close the modal after the action (inline async action pattern used by
   NewLeadButton), not on click.

2. **Client portal shows demo fiction to a real logged-in client.**
   With a real client account linked to a real project, the right rail is real
   (decisions, docs to sign, selections, budget, messages) but the center **project
   journal** ("Hi Tom & Kate — here's where we are", Marco tile posts, "TILE PHASE ·
   STARTED TODAY", "EXPECTED COMPLETION: JUN 18") and the **Money card**
   (Contract $58,400 / Paid $35,040 / Next draw $12,400) are hardcoded demo content —
   wrong client name and wrong money on a real client's page. Journal should come from
   daily logs/status (or an honest empty state) and Money from `getProjectMoney`.

3. **Sub portal is still the Marco/Henderson demo shell.** Same class as #2 — real sub
   logins get a fake "Today: Henderson kitchen" brief, fake scope checklist, fake money,
   fake watch-out. The real pieces built earlier (scope card, log composer, invoice
   submit, safety ack) are surrounded by fiction.

4. **Milestone auto-billing silently never fires.** Generating a contract *prints* the
   default draw schedule but never persists it (`estimates.draw_schedule` stayed NULL),
   so `advanceProjectStatus` had nothing to bill through construction → warranty.
   The signed contract promises draws the system then doesn't invoice. Fix: persist the
   draw schedule (with default triggers) at contract generation, or block generation
   until it's saved.

### P1 — stale demo data on core screens

5. **/chat project rooms are hardcoded wiped demo projects** (`lib/chat.ts:34-37`:
   henderson-kitchen, olson-porch, reyes-bath, chen-lead). Derive rooms from real
   active projects (46 exist; none shown).

6. **/files project tree is hardcoded demo** (Bauer/Chen/Henderson/Olson/Reyes under
   2024–2026) and the header claims "auto-organized · synced w/ Google Drive," which is
   false. Real per-project files (contracts, permits, uploads) exist but aren't
   browsable here. Build the tree from `projects` + `files.project_key`.

7. **/schedule AI conflict bubble fabricates a conflict from demo names on an empty
   week** ("Reschedule Brad's paint work at Reyes to avoid conflict with Henderson
   punch"). The conflict path is falling back to the mock's canned sentence. With no
   blocks it should say there's nothing to reschedule — never invent names.

8. **/ai starter chip** still says "Summarize where the Henderson kitchen stands."
   Generate starter chips from real records.

### P2 — real-data quality & UX

9. **Lead→project conversion naming:** "TEST QA Lead (Claude)" became project
   "Lead · Test kitchen + basement remodel (QA run — safe to delete)" — the last-name
   heuristic grabbed the word "Lead" and the whole scope string was used, producing an
   unusable name/slug. Let the owner edit the project name in a confirm step.

10. **Schedule week logic on weekends:** on Saturday Jul 4 the strip shows Mon Jun 29 –
    Fri Jul 3 (today isn't visible) and the label reads "JUN 29 – 3" (missing month).
    Show the week containing today (or roll to next week on Sat/Sun) and fix the label.

11. **Inbox "Needs reply" over-flags marketing.** 44 threads including Home Depot promos
    are tagged "AI: NEEDS YOUR REPLY". Exclude CATEGORY_PROMOTIONS/no-reply senders from
    the needs-reply view.

12. **First click after switching project tabs is sometimes lost** (New estimate / New
    change order needed a second click; reproduced repeatedly, ~1s after tab switch).
    Likely panel remount race in ProjectTabs. Users will read this as "button doesn't
    work."

13. **Warranty page on imported projects:** all 36 show "Closed Jul 3 2026" (import
    date), so warranty windows are computed from the import, and each card shows the
    project name duplicated as its subtitle. Needs real closed dates (or "closed date
    unknown") and client name in the subtitle.

14. **Rough-estimate amounts unformatted** ("4000-5000" → "$4,000–5,000").

15. **Projects list:** long AI status chips overlap the "0% billed" column on narrow
    rows (e.g. Dan Willems). Truncate/wrap the chip.

16. **Subs cards:** dangling "COI ·" chip when no expiry on file (say "COI missing");
    sub-detail still shows the static "1099 reminder · file by Jan 31" demo chip.

17. **Settings profile phone** is the placeholder (612) 555-0117 stored as real data —
    Joe should set his real cell (it feeds SMS-in later); consider clearing the seed value.
